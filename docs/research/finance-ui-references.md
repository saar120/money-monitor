# Finance UI references

Research snapshot: **6 November 2026**, with a containment refinement on **7 November 2026**. Scope: an app-wide design language for Money Monitor on desktop and iPhone. These are references for interface decisions, not recommendations to use financial products.

The strongest combination is Revolut for the financial overview, Mercury for desktop investigation, and Copilot for personal-finance review. Wise and Monzo add useful lessons about transaction scope and separating different financial questions. This is our interpretation of the evidence below; it does not imply that these products share one design system.

## Implications across the app

These are proposals for Money Monitor, to be specified in the [design language](../design-language.md):

- **One hierarchy:** page context, a primary amount or task, its relevant controls, then supporting detail. Reuse this order in Home, Accounts, spending analysis, budgets, and recurring payments. Settings and setup should use the same spacing and action hierarchy without artificial financial hero cards.
- **One path into evidence:** a category, chart segment, account, or attention item should open the relevant records with its scope preserved. Detail views should retain an obvious way back to that context.
- **One editing language:** use consistent row selection, category controls, review indicators, save feedback, and conflict handling. Desktop can offer compact rows and keyboard actions; iPhone should preserve the concepts with touch-sized controls and focused detail screens.
- **One visual grammar:** use a restrained surface hierarchy, readable numerals, consistent money/date alignment, and a small set of chart colors with stable meanings. Treat the exact palette, radius, spacing, typography, and motion as our own design decisions requiring contrast and layout checks.
- **Explicit financial meaning:** preserve Money Monitor's [Reporting Date, Saved View, and attention terminology](../../CONTEXT.md). A stale snapshot or account refresh problem should be visible where it affects a decision. Advisor interpretations should link back to their financial evidence.

## Contained without shouting

The stronger depth study made too many surfaces compete: the whole table, inspector, filters, category pills, and primary button all received elevation effects. Saar's feedback calls for clear grouping with less persistent visual emphasis. The following primary sources help distinguish containment from elevation:

| Source                                                                                                                                          | Verified guidance or behavior                                                                                                                                                                                                                   | Money Monitor interpretation                                                                                                                                                                   |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Linear's March 2026 interface refresh](https://linear.app/now/behind-the-latest-design-refresh)                                                | The team reduced navigation prominence, removed some colored icon backgrounds, softened structural borders, and moved the neutral palette toward warmer gray.                                                                                   | Keep the compact blue identity, but make navigation and repeated category treatments quieter. Use its reduction of visual competition without adopting a technical product tone.               |
| [Atlassian elevation guidance](https://atlassian.design/foundations/elevation)                                                                  | Default surfaces may use a border without lift. Raised surfaces should be used selectively; borders or spacing can suffice for grouping. Overlays represent UI above other UI. Dark themes also use surface lightness to communicate elevation. | Give the ledger and inspector a single fine perimeter and a surface tone. Reserve shadows for menus and other actual overlays. In dark mode, use modest tone changes rather than bright edges. |
| [Mercury Personal category editing](https://support.mercury.com/hc/en-us/articles/47117329500180-Categorizing-transactions-on-Mercury-Personal) | Categories can be edited from the transaction dropdown or from the detail panel.                                                                                                                                                                | Keep category editing directly accessible through text and a small chevron. A persistent raised pill is our design choice, not a prerequisite for the interaction.                             |

The proposed balance is one contained table, a subtle header band, quiet row dividers, plain category controls, and a separate inspector with the same treatment. Use a blue fill for selection, neutral hover, and an outline on the keyboard-focused control. Only the open picker needs an elevation shadow. Home can keep summary amounts unboxed while grouping related chart or list content; Review reuses the same table and inspector primitives.

These are design judgments informed by published guidance, not an experimentally established optimum. Validate the result at actual desktop size in both themes: groups should be recognizable before hover; the selected record and keyboard focus should be obvious; full amounts should stay readable; decorative lines should not dominate the data. Generated concepts illustrate the direction but do not certify layout dimensions, contrast, or working behavior.

## Boundaries of the research

This is a review of official documentation, published product imagery, and Mercury's public demo, not an authenticated audit or usability study. Help articles establish described workflows; they do not establish exact current spacing, motion, accessibility, or behavior in every country and subscription tier. No performance or usability advantage was measured.

Revolut's [Revolut 10 article](https://www.revolut.com/blog/post/revolut-10/) is dated October 2023. Its account switching and personalization remain useful historical reference points, but it should not be presented as the latest interface. Likewise, use Monzo's Trends evidence rather than treating retired Summary layouts as current.

The text fetch of [Wise Design](https://wise.design/) required JavaScript, and its linked [documentation endpoint](https://docs.wise.design/) redirected to a 404 page during this research. Current Wise component tokens were therefore **not verified**. Third-party reconstructions, exact token values, and old repository forks are deliberately excluded from the evidence.
