# Decision log

Record durable product and engineering choices here. A decision changes only through a new superseding entry; do not silently rewrite the rationale.

| ID    | Decision                                                                                                           | Rationale                                                                                                                                                                         | Status   |
| ----- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| D-001 | Build the native client in SwiftUI.                                                                                | Native navigation, accessibility, Charts, system search, and current Liquid Glass behavior are core requirements.                                                                 | Accepted |
| D-002 | Keep the Mac app and SQLite authoritative.                                                                         | Preserves the product's local trust boundary and existing scraper architecture.                                                                                                   | Accepted |
| D-003 | Use Tailscale HTTPS before any cloud service.                                                                      | Provides a private device-to-Mac path without moving credentials or authoritative data.                                                                                           | Accepted |
| D-004 | Target iOS 18 and build with the current stable iOS 26 SDK.                                                        | `Tab` and the search role are available from iOS 18; standard controls receive the new appearance on iOS 26 without abandoning older supported devices.                           | Accepted |
| D-005 | Use Liquid Glass only for navigation and controls.                                                                 | Financial content stays flat and readable; the system handles accessibility adaptations for standard controls.                                                                    | Accepted |
| D-006 | Add `/api/mobile/v1` rather than decode desktop database rows.                                                     | A versioned, masked, consistent DTO boundary prevents Swift models from coupling to SQLite.                                                                                       | Accepted |
| D-007 | Start read-only.                                                                                                   | The existing bearer token authorizes the full desktop API; mobile mutations need narrower capabilities and explicit product rules.                                                | Accepted |
| D-008 | Use XcodeGen and commit the generated Xcode project.                                                               | `project.yml` is reviewable and reproducible while the project opens directly in Xcode.                                                                                           | Accepted |
| D-009 | Use Swift Testing for unit/integration tests and XCTest for UI tests.                                              | Matches current Xcode project conventions and keeps UI automation on supported XCTest APIs.                                                                                       | Accepted |
| D-010 | Use Storage: None for the initial Xcode target.                                                                    | SQLite remains on the Mac; an encrypted snapshot cache will be designed as infrastructure, not mistaken for an authoritative model store.                                         | Accepted |
| D-011 | The private beta is owner-only and may pair multiple individually approved owner devices.                          | Supports replacement and multiple personal iPhones without inventing household roles or shared authorization.                                                                     | Accepted |
| D-012 | Mobile Access is opt-in and never a dependency for desktop startup.                                                | Tailscale absence or failure must not regress the authoritative Mac application.                                                                                                  | Accepted |
| D-013 | Use a separate mobile-only Fastify server behind Tailscale Serve.                                                  | Keeps desktop routes and the full desktop bearer token physically outside the mobile-facing listener. See [ADR-001](ADR-001-MOBILE-ACCESS-BRIDGE.md).                             | Accepted |
| D-014 | Pair with a five-minute single-use proof and issue one opaque 256-bit token per approved device.                   | Explicit approval plus digest-only Mac storage and Keychain-only iPhone storage provides durable revocation without sharing desktop authority.                                    | Accepted |
| D-015 | Persist one stable server ID and version the pairing protocol and mobile API independently, starting at version 1. | Identity and compatibility must survive app restarts and evolve without coupling to marketing versions.                                                                           | Accepted |
| D-016 | Own a dedicated Tailscale Serve HTTPS listener on port 8443 and fail closed on conflict.                           | A stable explicit listener avoids rewriting unrelated Serve configuration or silently changing the paired URL. See [ADR-001](ADR-001-MOBILE-ACCESS-BRIDGE.md).                    | Accepted |
| D-017 | Return `426 upgrade_required` before decoding bootstrap feature data.                                              | Incompatibility must remain distinguishable from malformed data and must never replace a valid cache; a small error envelope stays decodable even when the feature schema is not. | Accepted |
| D-018 | Defer Phase 1 for the current single-owner technical dogfood and begin a live-only Phase 2A Home slice after Phase 0. | The exception is limited to the sole owner on a passcode-protected, non-shared personal iPhone. The validated bootstrap remains memory-only while app lock, encrypted offline snapshots, polished onboarding, and full accessibility acceptance wait. Foregrounding may reveal data without another app-authentication prompt until Phase 1 resumes, so an app-switcher privacy cover is pulled forward before real values render. Phase 1 remains required before broader distribution or offline storage. | Accepted |
